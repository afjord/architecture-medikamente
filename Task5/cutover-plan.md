## Выбор стратегии:

В качестве стратегии выбрана Parallel Run.

## Обоснование выбора:

Для медицинской организации критически важны непрерывность бизнес-процессов, сохранность медицинских данных и
возможность быстрого восстановления работы при возникновении ошибок. По этой причине выбрана стратегия Parallel Run,
предполагающая параллельную эксплуатацию старой и новой систем в течение переходного периода.

### Преимущества:

* минимизация риска потери данных;
* возможность поэтапной миграции пользователей;
* упрощённый откат;
* возможность сравнения результатов работы систем.

### Недостатки:

* необходимость синхронизации данных;
* временное увеличение затрат на сопровождение;
* усложнение мониторинга.

### Альтернативы:

1. High-Level Design не был выбран, т.к. он по своей сути не является cutover стратегией.
2. Чистый Branch by Abstraction не был выбран, потому что текущая система - это не один монолит, который можно
   постепенно
   разрезать через интерфейсы. У нас:

    * Excel;
    * файловый сервер;
    * сканы PDF/JPG;
    * 1С;
    * Exchange;
    * ручные процессы.

   Branch by Abstraction хорошо работает, когда есть кодовая база, которую можно постепенно рефакторить.

## План отката:

| Сценарий                      | Действие                                     |
|-------------------------------|----------------------------------------------|
| Ошибки миграции данных        | Возврат к старой системе                     |
| Недоступность новой платформы | Переключение пользователей на старую систему |
| Некорректные расчёты          | Блокировка новой системы и анализ            |
| Сбой интеграций               | Возврат на старые процессы                   |
