### Обоснование необходимости защиты:

| Категория          | Причины                                                                                                    |
|--------------------|------------------------------------------------------------------------------------------------------------|
| Медицинские данные | Врачебная тайна<br>Специальные категории ПДн<br>Высокий репутационный ущерб<br>Требования законодательства |
| ПДн                | 152-ФЗ<br>Возможность идентификации пациента<br>Риск мошенничества                                         |
| Учётные данные     | Компрометация аккаунтов<br>Несанкционированный доступ к медданным                                          |
| Финансовые данные  | Финансовые потери<br>Мошенничество                                                                         |

### Средства защиты:

| Данные     | Data at Rest            | Data in Transit |
|------------|-------------------------|-----------------|
| ПДн        | AES-256                 | TLS 1.3         |
| Медкарты   | AES-256 + KMS           | TLS 1.3 + mTLS  |
| Анализы    | AES-256 + KMS           | TLS 1.3 + mTLS  |
| Платежи    | AES-256                 | TLS 1.3         |
| Пароли     | Argon2id                | HTTPS           |
| Токены     | Зашифрованное хранилище | TLS 1.3         |
| Audit Logs | Шифрование диска        | TLS 1.3         |

### Автоматизированный контроль:

1. Keycloak контролирует аутентификацию, MFA, роли.
2. OPA контролирует ABAC, доступ к медицинским данным.
3. SIEM отправка алертов в случае массового чтения карт, выгрузки большого объёма данных, доступ в нерабочее время.
4. DLP контроль утечки данных.
5. Data Discovery (Apache Atlas) для поиска конфиденциальных данных.
